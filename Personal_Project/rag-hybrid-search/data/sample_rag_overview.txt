Retrieval-Augmented Generation (RAG)

Introduction
------------
Retrieval-Augmented Generation (RAG) is a natural language processing technique that
enhances large language models (LLMs) by providing them with relevant external knowledge
at inference time. Rather than relying solely on information encoded in the model's
weights during training, RAG systems retrieve documents from a knowledge base and
inject them into the model's context window.

This approach offers two key advantages. First, it allows the model to answer questions
about information that was not present in its training data. Second, it reduces
hallucination by grounding the model's responses in retrieved evidence.

Dense Retrieval
---------------
Dense retrieval encodes documents and queries as continuous vector representations
(embeddings) using a neural encoder, typically a transformer-based bi-encoder.
The similarity between a query and a document is computed as the dot product or
cosine similarity of their embeddings.

Popular embedding models include:
- all-MiniLM-L6-v2: 22M parameters, 384-dimensional embeddings, very fast
- all-mpnet-base-v2: 110M parameters, higher quality but slower
- text-embedding-3-small: OpenAI's API-based embedding model

Dense retrieval is stored in a vector database (e.g., ChromaDB, Pinecone, Weaviate)
which uses approximate nearest-neighbour algorithms like HNSW for fast retrieval.

Sparse Retrieval (BM25)
-----------------------
BM25 (Best Match 25) is a probabilistic retrieval model based on term frequency and
inverse document frequency. It scores documents by how often query terms appear in
them, normalised by document length.

The BM25 formula is:
  score(D, Q) = Σ IDF(q) * (f(q,D) * (k1+1)) / (f(q,D) + k1 * (1 - b + b * |D|/avgdl))

Where:
- f(q, D) = term frequency of query term q in document D
- |D| = document length
- avgdl = average document length in the corpus
- k1 (typically 1.2–2.0) = term frequency saturation parameter
- b (typically 0.75) = length normalisation parameter

BM25 excels at exact keyword matching and is particularly effective for queries
containing rare technical terms, proper nouns, and acronyms.

Hybrid Search and RRF
---------------------
Hybrid search combines dense and sparse retrieval to get the benefits of both.
Dense retrieval captures semantic meaning, while sparse retrieval captures exact
keyword matches. The two result lists are merged using Reciprocal Rank Fusion (RRF).

RRF scores each document as:
  RRF(d) = Σ 1 / (k + rank_i(d))

Where k=60 is a smoothing constant and rank_i(d) is the document's rank in result list i.
RRF is robust because it uses ranks rather than raw scores, avoiding scale mismatch.

Cross-Encoder Reranking
-----------------------
After hybrid retrieval, a cross-encoder reranker improves result ordering.
Unlike bi-encoders that encode query and document separately, a cross-encoder
takes the concatenation [query; document] as input and outputs a single relevance score.

This joint encoding allows the model to capture fine-grained query-document
interactions that bi-encoders miss. The trade-off is higher inference cost:
cross-encoders cannot pre-compute document embeddings, so they must process each
query-document pair at query time.

The standard approach is to run cross-encoder reranking on the top 20–40 candidates
from hybrid retrieval, not the full corpus.

Popular reranking models:
- cross-encoder/ms-marco-MiniLM-L-6-v2 (fast, good quality)
- cross-encoder/ms-marco-electra-base (higher quality, slower)
- rerank-english-v3.0 (Cohere API)

Chunking Strategies
-------------------
How documents are split into chunks significantly affects RAG quality.

1. Fixed-size chunking: Split every N tokens. Simple but may cut sentences mid-way.

2. Recursive character splitting: Split on paragraph → sentence → word boundaries.
   Tries to preserve semantic units. Good general-purpose choice.

3. Sentence-aware chunking: Groups complete sentences until token budget is reached.
   Preserves meaning, best for QA tasks.

4. Sliding window: Fixed-size windows with overlap. Ensures no context is lost
   at chunk boundaries. Useful for long, continuous documents.

Chunk size is typically 256–1024 tokens with 10-20% overlap.
Larger chunks provide more context but dilute relevance signals.
Smaller chunks are more precise but may miss surrounding context.

Evaluation Metrics
------------------
RAG systems are evaluated on multiple dimensions:

Faithfulness: Are all claims in the answer supported by the retrieved context?
A faithfulness score of 1.0 means every statement can be traced to the context.

Answer Relevance: Does the answer actually address the user's question?
Measured by LLM judge or embedding similarity between question and answer.

Context Precision: Of the retrieved chunks, what fraction are actually relevant?

Context Recall: Of all relevant chunks in the corpus, what fraction were retrieved?

MRR (Mean Reciprocal Rank): Average of 1/rank of the first relevant result.
Useful when you care about the position of the first relevant hit.

NDCG (Normalised Discounted Cumulative Gain): Measures ranking quality
accounting for position — relevant results at position 1 are worth more than at position 10.
