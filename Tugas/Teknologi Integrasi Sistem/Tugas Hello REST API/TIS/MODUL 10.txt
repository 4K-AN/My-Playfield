MODUL 10

DOKUMENTASI DAN VERSIONING API

A. TUJUAN PRAKTIKUM
1. Memahami konsep dasar API Documentation pada REST API yang telah dibangun.
2. Menjelaskan pentingnya dokumentasi API sebagai kontrak antara client dan server.
3. Memahami konsep API Versioning untuk mengelola perubahan API.
4. Menerapkan URI Versioning pada endpoint API.
5. Membuat dokumentasi API interaktif menggunakan OpenAPI/Swagger.
6. Mengintegrasikan dokumentasi dan versioning pada studi kasus Student API berbasis database.

B. PRA-PRAKTIKUM
Bagian 1: Keterkaitan dengan Modul 09
1. Gunakan project Laravel yang sama dengan Modul 09, sehingga data Student dan Course sudah
tersimpan di database melalui Eloquent ORM.
2. Pastikan project telah memiliki tabel students, courses, dan course_student, serta endpoint CRUD
Student, JWT authentication, authorization berbasis role, dan API Gateway.
3. Pastikan endpoint berikut sudah berjalan sebelum memulai modul ini: POST /api/login, GET /api/profile,
GET /api/students, GET /api/students/{nim}/courses, dan GET /api/gateway/students. 4. Jalankan server
Laravel dengan perintah berikut.
php artisan serve
Bagian 2: Memahami Dokumentasi API
Dokumentasi API adalah panduan penggunaan API yang memuat endpoint, parameter, request, response,
status code, dan kebutuhan authentication. Dokumentasi berfungsi sebagai kontrak antara client dan server
sehingga frontend, backend, maupun pihak ketiga memiliki pemahaman yang sama tentang cara
menggunakan endpoint yang tersedia.
Pada studi kasus lanjutan dari Modul 09, dokumentasi menjadi penting karena Student API sudah
menggunakan database. Artinya, API tidak lagi bersifat simulatif, tetapi mulai menyerupai sistem nyata yang
harus dapat dipahami, diuji, dan dipelihara oleh developer lain.
Bagian 3: Komponen Dokumentasi API
1. Endpoint API
2. HTTP Method seperti GET, POST, PUT, PATCH, dan DELETE
3. Parameter, baik query, path, maupun body
4. Format request, umumnya JSON
5. Format response
6. Status code
7. Authentication
Bagian 4: Instalasi Swagger pada Project
1. Install package Swagger pada project Laravel dengan perintah berikut.

composer require darkaonline/l5-swagger
2. Publish konfigurasi Swagger.
php artisan vendor:publish --provider="L5Swagger\L5SwaggerServiceProvider"
3. Generate dokumentasi awal.
php artisan l5-swagger:generate
4. Jika berhasil, dokumentasi dapat diakses melalui browser pada alamat berikut.
http://127.0.0.1:8000/api/documentation

Bagian 8: Menerapkan API Versioning pada Studi Kasus Modul 09
8.1. Konsep Versioning
API Versioning adalah teknik untuk mengelola perubahan API agar client lama tidak rusak ketika struktur
response atau perilaku endpoint berubah. Tanpa versioning, perubahan field atau struktur response dapat
menyebabkan client lama error, integrasi pihak ketiga gagal, dan maintenance menjadi sulit.
Pada modul ini digunakan strategi URI Versioning karena paling mudah dipahami dan diimplementasikan
pada tahap pembelajaran.

8.3. Uji Endpoint v1
1. Lakukan pengujian endpoint ping versi 1.
GET http://127.0.0.1:8000/api/v1/ping
2. Response yang diharapkan adalah sebagai berikut.
{
"version": "v1",
"message": "pong"
}
3. Uji juga login versi 1.
POST http://127.0.0.1:8000/api/v1/login
{
"email": "admin@example.com",

}
8.4. Uji Gateway v1
1. Lakukan request berikut untuk menguji gateway versi 1.
GET http://127.0.0.1:8000/api/v1/gateway/students
Authorization: Bearer <jwt-token-admin>
Accept: application/json
Karena studi kasus ini melanjutkan Modul 09, data student yang tampil pada response harus berasal dari
database, bukan lagi dari array hardcode.
Bagian 9: Membuat Simulasi API v2 Berdasarkan Data Database
9.1. Menambahkan Route v2
Route::prefix('v2')->group(function () {
Route::get('/ping', function () {
return response()->json([
'version' => 'v2',
'message' => 'pong',
'documentation' => 'This is API version 2'
]);
});
Route::get('/students', [StudentController::class, 'indexV2']);
});
9.2. Menambahkan Method indexV2()
public function indexV2()
{
$students = \App\Models\Student::with('courses')->get()->map(function ($student) {
return [
'nim' => $student->nim,
'nama' => $student->nama,
'program_studi' => $student->program_studi,
'status' => 'active',
'mata_kuliah_count' => $student->courses->count()
];

});
return response()->json([
'version' => 'v2',
'message' => 'Student data with new response format',
'data' => $students
]);
}
9.3. Membandingkan v1 dan v2
1. Uji endpoint v1: GET http://127.0.0.1:8000/api/v1/students
2. Uji endpoint v2: GET http://127.0.0.1:8000/api/v2/students
3. Amati bahwa v1 masih menggunakan struktur lama, sedangkan v2 menambahkan program_studi, status,
dan mata_kuliah_count.
